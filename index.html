    How Tracker Lens works

    A website is rarely built by one company alone. While a page loads, your browser quietly talks to many other companies. This guide explains what that means, how Tracker Lens measures it, and how to run a fair comparison.

    What happens on a visit

    When you type an address such as example-news.com, your browser first downloads the page itself from that website. The page then tells the browser to fetch many more pieces: images, fonts, scripts, videos, ads. Many of these pieces do not come from the website you opened. They come from other companies.

    Each piece is a separate request: the browser asks a server for a file and gets an answer. A typical news page makes a few hundred requests, often to 50 or more different companies, within the first seconds. None of this is visible on the page. It looks the same whether it talked to two companies or eighty.

    What companies learn from a request

    A request is not only a download. It also carries information to the company that answers it:

    • Which site you are on. The browser tells the server where the request comes from. Scripts loaded from that company can also read the full address of the page you are reading.
    • Who you are, roughly. Your IP address, browser, language, screen size and time zone go with every request. Together they can recognise a browser even without cookies.
    • Whether they have seen you before. A company can store a cookie with an ID in your browser. When another website loads something from the same company, that cookie comes back, and the company knows the same browser visited both sites. Firefox and Safari block many of these cookies by default; Chrome still allows most of them.
    • What other companies call you. Ad companies exchange their IDs for the same browser, a practice called cookie syncing. In a HAR file it shows up as a burst of short requests to many ad domains at once.

    On pages with ads, there is usually an auction behind the scenes: the page asks several ad companies what they would pay to show you an ad. Every company asked in that auction appears as an outside domain.

    Kinds of outside domains

    Tracker Lens does not sort domains into groups, but knowing the common kinds helps you read your results. Some outside domains are needed for the page to work. Others exist only to measure or target visitors.

    A content delivery domain usually just hands out files, but it still sees which site you are on. A tag manager on its own collects little, yet it often loads many of the other kinds.

    What Tracker Lens counts

    For every page in your file, Tracker Lens counts the outside domains: the different websites, other than the one you opened, that your browser contacted while that page was loaded.

    It counts companies, not requests, on purpose. One ad server can send fifty requests, but it is still one company that learned about the visit. The number of requests is shown too, in the page list, because it tells you how busy each company was.

    How the count is calculated

    1. Find the pages. A HAR file lists every request and, for most browsers, which page load it belongs to. Every page load becomes one page in Tracker Lens. If a file has no page information, the whole file is treated as one page.
    2. Find the main domain of each request. The address is shortened to the part a company registers. Subdomains are dropped, so all addresses of one company's domain count once.
    3. Compare with the page. If the main domain of a request differs from the main domain of the page, the request is outside.
    4. Count. For each page: the number of different outside domains, and the number of outside requests. For each file: the average over its pages.

    Step 2 for a few real addresses, on a page of example-news.com:

    Recording a HAR file

    A HAR file (HTTP Archive) is a recording of the requests your browser made, saved from the browser's developer tools. Every major browser can create one.

    Chrome and Edge

    1. Press F12 (on a Mac ⌥ ⌘ I) and open the Network tab.
    2. Tick Preserve log and Disable cache.
    3. Click the clear button, then visit your pages.
    4. Click the download arrow in the Network toolbar, or right click the list and choose Save all as HAR.

    Firefox

    1. Press F12 and open the Network tab.
    2. In the gear menu, turn on Persist Logs. Tick Disable Cache.
    3. Clear the list, then visit your pages.
    4. Right click the list and choose Save All As HAR.

    Safari

    1. In Settings, Advanced, turn on the developer features.
    2. Open Develop, Show Web Inspector, Network.
    3. Turn on Preserve Log, then visit your pages.
    4. Click Export in the Network tab.

    For a clean recording:

    • Use a private window, so earlier visits and logins do not affect the result.
    • Open each page by typing or pasting its address, so every visit becomes its own page in the file.
    • Stay on each page for about 30 seconds and scroll down once. Many ads and trackers only load after a delay or when you scroll.
    • Decide beforehand how you answer cookie banners, and answer them the same way on every site.
    • Pages that change content without reloading, such as some web apps, stay one page in the file.

    What the files show

    Outside domains per page
    One row per file. The large number is the average count of outside domains per page, over all pages including noise. Click a name to rename the file.
    Site by site
    Every website from every file, in two groups. Compared lists the websites found in every file, with the change from the baseline. Below it, websites found in only one file are listed per file and marked as noise or not compared. A website you opened several times shows the average of those visits. The bar chart below shows the plain average over all pages, noise included, so use the table for the fair comparison.
    What changed on the compared websites
    Which outside domains are new or gone on the websites found in every file. This is usually the clearest sign of what your change did. Domains that only the noise websites contacted are listed separately, folded away.
    Every page
    Every page of a file, in the order you visited them. Noise websites carry a noise website label. Open a page to see each outside domain with its number of requests, longest bar first.
    CSV export
    One row per page with the columns file_label, is_baseline, page_url, site, compared (whether the website is in every file), third_party_domains and third_party_requests, ready for a spreadsheet or statistics software.

    Designing a comparison

    One file shows how a set of websites behaves. Two files show what a change does. Record the same websites twice and change exactly one thing in between. Questions you can answer this way:

    • How many companies disappear when I reject cookies instead of accepting them?
    • How much does an ad blocker or a privacy browser reduce the number of outside domains?
    • Does a browser profile that has been browsing for a week attract more companies than a fresh one?
    • Do the same news sites behave differently in another country or on a phone?

    To keep the comparison fair:

    • Visit the same websites, in the same order, with the same time on each page.
    • Record both sessions close together in time. Ad activity changes over the day and the week.
    • Record each session at least three times and load all files. If the differences between your repeats are as large as the difference between your two setups, the change probably did nothing.
    • Name each file after its setup, for example accept-1 and reject-1, and write down when and how you recorded it.

    Testing noise

    Trackers build a picture of you from the sites you visit. If you mostly read about cars, you become "interested in cars". Noise is the idea of hiding that picture by also visiting unrelated sites, such as cooking, travel or gardening. The question is whether the companies watching you notice the difference, or simply carry on. This tactic is known as obfuscation.

    Tracker Lens has no noise setting. You create the noise yourself while recording, and Tracker Lens compares the result.

    Recording a noise comparison

    1. Pick your topic sites. For example five car sites. These are the sites you compare.
    2. Pick your noise sites from other topics, for example two cooking, two travel and two sports sites.
    3. Record without noise. In a fresh private window, visit only the topic sites. Save the file as no-noise.har.
    4. Record with noise. In a new fresh private window, visit the same topic sites in the same order, with noise sites in between. Save it as noise.har.
    5. Load both files. The first file becomes the baseline. If you loaded them the other way round, click Make baseline next to the file without noise.

    Tracker Lens compares only websites found in both files. The noise sites appear in one file only, so Tracker Lens recognises them as noise, reports their share of all visits, and leaves them out of the comparison. What you see is how the topic sites behaved with and without noise around them.

    To tell your files apart later, give them clear names before exporting, such as cars-no-noise.har and cars-noise-30.har. Tracker Lens also shows each file's recording time, browser and visited websites.

    Setting the amount of noise

    The amount of noise is the share of noise visits among all visits. You set it by how many noise sites you visit per topic site.

    AmountShare of noiseExample with 6 car sites
    None0%6 car sites
    Lightabout 30%6 car sites and 3 noise sites: one noise site after every second car site
    Heavyabout 70%6 car sites and 14 noise sites: two or three noise sites after every car site

    There are two ways to add noise, and they answer different questions:

    Adding noise on top
    You keep all topic visits and add noise visits. The browsing session gets longer. This tests whether the same interest gets blurred when it is surrounded by other topics. The table above uses this way.
    Replacing visits with noise
    You keep the total number of visits and swap some topic visits for noise visits, for example 4 car sites and 2 noise sites instead of 6 car sites. This tests what happens when the real interest gets weaker. Only the car sites you kept can be compared across files.

    Choosing noise sites

    • Use sites that carry ads and trackers themselves. Sites without trackers add no noise that anyone sees.
    • Mix several topics. Noise from a single topic just creates a second interest.
    • Avoid topics that advertisers pay a lot for, such as finance, insurance or travel bookings. They can make a profile more attractive instead of blurring it.
    • Never log in anywhere during a recording. A login ties all visits to you directly, and noise no longer hides anything.

    What to look for

    • The first finding: check that the websites named as noise really are your noise sites, and that the noise share matches what you planned.
    • Site by site: did the topic sites contact more or fewer companies when noise was present?
    • What changed on the compared websites: which companies are new or gone on the topic sites when noise was present? Domains that only the noise sites contacted are listed apart from these.
    • Repeats: record each setup at least three times. Any effect of noise may be small, and ad activity varies a lot between visits.

    Tracker Lens shows who was contacted, not what they concluded. If the same companies are contacted with and without noise, they may still have built a different picture of you. Measuring that needs the ad prices or interest labels companies attach to a browser, which a HAR file usually does not contain.

    What it cannot tell you

    • What the companies did with the information. A contacted domain may be a harmless font server or an ad network building a profile. The count does not tell them apart.
    • Who owns a domain. Several domains can belong to one company, for example doubleclick.net and googletagmanager.com both belong to Google. They are counted separately.
    • A site's own other domains. Some sites load files from a second domain they own, such as a separate image domain. Tracker Lens cannot know that and counts it as outside.
    • Disguised trackers. Some trackers run under a subdomain of the site itself, such as metrics.example-news.com. They look like part of the site and are not counted.
    • Anything your browser did not load. Companies also share data directly between their servers. That never appears in a HAR file.
    • Rare domain endings. Two part endings such as co.uk come from a short built in list, not the full official list. A few uncommon endings may be grouped wrongly.

    Results also vary from visit to visit, because ads and tracking scripts change with time and demand. A single recording is one observation, not a fact about a website.

    Your data

    The file is read inside this browser tab and never sent anywhere. There is no server behind this page, and it also works offline if you download it.

    Be careful when sharing HAR files with other people. They contain every address you visited during the recording and, depending on the browser, can contain cookies, login tokens or form entries. Recent versions of Chrome remove cookies when exporting by default. Record in a private window without logging in anywhere, and the file stays harmless.

    Terms used here

    Request
    One file the browser asks a server for: an image, a script, a pixel, a piece of data.
    Domain
    The name of a server in an address, such as securepubads.g.doubleclick.net.
    Main domain
    The part of a domain that a company registers, such as doubleclick.net. Also called the registrable domain.
    First party
    The website you opened, including all its subdomains.
    Outside domain
    Any main domain other than the first party. Also called a third party.
    Cookie
    A small piece of text a server stores in your browser and receives back on later requests. Often holds an ID.
    HAR file
    A recording of all requests in a browser session, in a standard format every browser can export.

    Tracker Lens groups addresses by their main domain using a short built in list of endings such as co.uk, so a few rare endings may be grouped imperfectly. Source code on GitHub
